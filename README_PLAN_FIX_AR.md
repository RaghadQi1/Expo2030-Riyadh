# Expo2030 — إصلاح إنشاء الخطة وحفظها

## ما المشكلة؟

في الإصدار السابق، كانت قائمة «تجربة ما تبغى تفوتك؟» تعرض 96 فعالية بدون مراعاة الوقت المختار. وعند تثبيت فعالية خارج الوقت، كان الخادم يرفض الطلب بالكامل برسالة `الفعالية المثبّتة تقع خارج وقت الزيارة`، بدل إنشاء خطة باستخدام اختيارات مناسبة.

## ما الذي تغير؟

- شاشة Swift تعرض الفعاليات ذات المواعيد المتوافقة مع مدة الزيارة. وأضفنا بداية/نهاية الفعالية بالـدقائق إلى واجهة API.
- إذا غيّرتِ وقت الزيارة بعد تثبيت فعالية، فلن تتعطل العملية: الخادم يتجاهل الأولوية الخارجة عن الوقت أو المتعارضة **ويعرضها في ملاحظات الخطة**، من دون نقل مواعيد الفعاليات أو اختراع بيانات.
- Gemini يرتب معرفات فعاليات (`E...`) وبوثات (`B...`) حقيقية من **ملفات المحاكاة** الموجودة مع المشروع. بايثون يتحقق من التعارضات وأوقات الفعاليات وساعات فتح البوثات، ويضيف زيارة بوث مرنة تقديرية مدتها 20 دقيقة عندما يناسب الوقت.
- بعد الضغط على «اعتمد» في شاشة الخطة، يرسل Swift الخطة إلى `PUT /plans/current` ويحفظها الخادم تحت `user_state.kind = 'plan'` في `instance/expo_users.sqlite3`. لا تُعرض كخطة معتمدة محليًا إلا بعد نجاح الحفظ.
- أصلحنا عرض رسائل الخطأ الفعلية للـFlask في تطبيق Swift.

**تنبيه:** عند اختيار وقت خارج ساعات عمل جميع البوثات والفعاليات، أو تعذر الوصول إلى Gemini، سيظهر خطأ واضح بدل إنشاء مواعيد وهمية. نجاح الاختبارات المحلية لا يضمن استقرار الإنترنت أو توفر خدمة Gemini الخارجية.

## تشغيل النسخة المصححة (Mac + iPhone Simulator)

1. فكّي الضغط عن ملف ZIP الجديد وافتحي مجلد `Expo2030/backend` الناتج.
2. افتحي Terminal في هذا المجلد، ثم:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

3. لإنشاء الإعدادات للمرة الأولى فقط، إذا **لم يوجد** ملف `.env`:

```bash
cp -n .env.example .env
code .env
```

4. داخل `.env` ضعي `GEMINI_API_KEY=...` (مفتاحك الحقيقي) و`GEMINI_MODEL=gemini-2.5-flash` ثم احفظي. **لا تضعي المفتاح في Xcode أو GitHub، ولا ترسلي الملف إلى أحد.** إذا كان عندك `.env` قديم انسخي المفتاح منه بطريقة آمنة، ولا تنفذي `cp .env.example .env` بشكل قد يستبدل الملف.
5. شغّلي السيرفر:

```bash
python3 -m app.main
```

6. افتحي `Expo2030.xcodeproj` في Xcode، اختاري محاكي الآيفون، وتأكدي أن `EXPO_API_MODE=live` في **Product → Scheme → Edit Scheme → Run → Arguments**. شغّلي بـ `⌘R`، وسجلي الدخول، واختاري تفضيلاتك، ثم اضغطي **«كوّن خطتي»**.
7. بعد ظهور الخطة، اضغطي **«اعتمد»**. عندها فقط تصبح الخطة محفوظة كخطتك الحالية في SQLite.

## التحقق من الحفظ

في Terminal جديد داخل `backend`، بعد اعتماد الخطة:

```bash
sqlite3 instance/expo_users.sqlite3 \
"SELECT u.email, s.kind, s.updated_at FROM user_state s JOIN users u ON u.id=s.user_id WHERE s.kind IN ('plan','preferences');"
```

للتحقق من محتوى الخطة:

```bash
sqlite3 instance/expo_users.sqlite3 \
"SELECT substr(payload,1,300) FROM user_state WHERE kind='plan';"
```

إذا ظهرت `plan` بعد الاعتماد، فالخطة محفوظة في هذا الملف. ملف ZIP **لا يحتوي** على حساباتك القديمة أو ملف `.env` الخاص بك. إن أردتِ نقل حسابات سابقة، احتفظي بنسخة `instance/expo_users.sqlite3` من المشروع القديم وانقليها إلى الجديد **والسيرفر متوقف**؛ تجنبي استبدال قاعدة بيانات فيها حسابات جديدة.

## الاختبارات

```bash
cd backend
python3 -m unittest discover -s tests -p 'test_gemini_planner.py' -v
python3 -m unittest discover -s tests -p 'test_user_persistence.py' -v
```

واختبار تسجيل مستخدم فعليًا عبر مسارات Flask، بدون إرسال طلب إلى Gemini:

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest tests/test_plan_generation_api.py -q
```

**نطاق التحقق عند تسليم هذه النسخة:** نجحت اختبارات منطق الخطة والتخزين بـSQLite محليًا، وكذلك فك/قراءة زمن الفعالية من JSON في Swift مع Foundation. لا أستطيع تشغيل محاكي Xcode على هذه البيئة، أو اختبار اتصال Gemini الحقيقي بدون مفتاحك وإنترنت الخادم.
