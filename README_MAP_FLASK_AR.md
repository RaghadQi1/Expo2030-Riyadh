# دمج خريطة إكسبو 2030 – نسخة iOS + Flask + SQLite

هذه النسخة مبنية على **المشروع الأول** `2030Expo-iOS(3).zip` بالكامل. استُخدمت **ملفات خريطة المشروع الثاني** `Expo 2030 Ai 2.zip` نفسها (SceneKit للخارج، وSwiftUI Canvas للداخل) في تبويب «الخريطة». لم تُستبدل شاشات الخطة أو الحساب أو الاستكشاف أو الرحلة أو المساعد، ولم تُعد كتابة خدماتها.

## الملفات التي تغيّرت

- `Expo2030/Features/Map/MapTab.swift`: احتفظت بالخريطة القديمة وكل وظائفها تحت اسم `LegacyMapTab`، بدل حذفها.
- `Expo2030/Features/Map/ExpoMapV2/`: ملفات الخريطة الأصلية من المشروع الثاني مع `MapTabAdapter.swift` للتشغيل داخل التطبيق الأول. تغيّر اسما نوعين فقط (`MapPoint` إلى `ExpoNavPoint` و`ExpoEvent` إلى `ExpoNavEvent`) لمنع تضاربها مع الأنواع الموجودة مسبقًا في المشروع الأول.
- `Expo2030/Resources/ExpoMapData/`: نسخنا ملفات JSON الأصلية للخريطة والفعاليات والبوابات والممرات. تظل صالحة عند توقف الخادم (offline fallback).
- `Config/Info.plist`: أضفنا `EXPO_API_BASE_URL` وتسهيلات شبكة محلية **للتطوير فقط**.
- `backend/`: كود Flask API وSQLite وملف نموذج الذكاء الاصطناعي الاصطناعي الأصلي من المشروع الثاني، بدلاً من FastAPI.

## تعديلات الواجهة (الخريطة فقط)

1. الخريطة **الخارجية** ثلاثية الأبعاد SceneKit بجميع عناصر وعلامات المشروع الثاني، مع اختيار البوابات والأجنحة والفعاليات.
2. الخريطة **الداخلية** ذات دورين، وتحديد البداية والوجهة، والممرات المرسومة والمسارات الممكنة.
3. زر «الأوقات» في الخريطة الداخلية صار يفتح **نافذة سفلية مستقلة** قصيرة بدل عرض أزرار الساعة على مساحة كبيرة من الخريطة. الساعات المختارة لا تزال ترسل الطلب نفسه للـ API وتغيّر توقّع الزحمة وتكلفة المسار إذا توفرت النتيجة.
4. بطاقة اقتراح المسار أسفل الخريطة الداخلية أصغر: سطر الوجهة، خيارا أسرع/أقصر بشكل مضغوط، معلومات الازدحام في سطر واحد، وزر بدء المشي. لا حاجة لتمرير بطاقة طويلة تغطي الخريطة.
5. أبقينا مساحة **82 نقطة** أعلى شريط التبويبات العائم للتطبيق الأول حتى لا يغطي أزرار بطاقة الخريطة. لم نلغ شريط التبويبات أو المساعد.
6. روابط الخريطة القديمة القادمة من شاشات المشروع الأول تُوجّه للخريطة الجديدة عندما تتطابق الـ IDs، أو تفتح الخريطة القديمة كما هي لميزات الأصدقاء/نقطة الالتقاء/العناصر غير المتوافقة. **البيانات القديمة والجديدة منفصلتان، ولم تُوحّد IDs الخاصة بهما**؛ لذلك هذه طبقة توافق وليست دمجًا لجميع وظائف الخرائط.

## تشغيل الـ Backend على Mac

افتح Terminal داخل مجلد `backend`:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m app.main
```

سيعمل على `http://127.0.0.1:8001` (للـ iPhone Simulator على نفس جهاز الـ Mac). افحص:

```bash
curl http://127.0.0.1:8001/health
curl http://127.0.0.1:8001/api/v1/dataset
curl http://127.0.0.1:8001/api/v1/crowd/model-info
```

التوقع في الساعة 11 صباحاً ويوم الأحد (اليوم مرمّز من 0 للأحد إلى 6 للسبت):

```bash
curl 'http://127.0.0.1:8001/api/v1/crowd/predict?hour=11&day=0&zone=0&floor=1'
```

لجلب توقع الممرات كما يفعل Swift:

```bash
curl -X POST http://127.0.0.1:8001/api/v1/crowd/indoor-edges \
  -H 'Content-Type: application/json' \
  -d '{"hour":11,"day":0,"edges":[{"edge_id":"f1/example-demo-segment","floor":1,"x":385,"y":290}]}'
```

## تشغيل تطبيق الآيفون

1. شغّل الـ Backend أولًا.
2. افتح `Expo2030.xcodeproj` في Xcode، واختر iPhone Simulator.
3. شغّل التطبيق بالطريقة المعتادة ثم افتح تبويب «الخريطة»؛ ستظهر الخريطة الخارجية من المشروع الثاني.
4. اضغط جناح السعودية، ثم «دخول جناح السعودية». داخل الجناح اختر «الفعاليات» أو نقطة مباشرة من الرسم، وسيحسب Swift المسار حسب ممرات `NavigationGraph`.
5. اضغط «الأوقات» لتجربة أوقات مختلفة. يُرسل تطبيق Swift توقّعات **كل ممر** للـ API، ثم يعيد Dijkstra حساب أسرع طريق محليًا. إذا الخادم مغلق، يعمل الرسم والبحث والمسارات على بيانات JSON الافتراضية، وتظهر الزحمة غير متاحة.
6. لا تحتاج مفتاح Gemini؛ النموذج الموجود هو **RandomForestRegressor محفوظ مسبقًا**، وليس Gemini أو اتصالًا بسيرفر AI خارجي.

**على آيفون حقيقي:** لن يشير `127.0.0.1` إلى جهاز Mac بل إلى الآيفون نفسه. استبدله بعنوان IP المحلي للـ Mac داخل `Config/Info.plist` في `EXPO_API_BASE_URL` (مثال: `http://192.168.1.10:8001`) وشغّل الـ Flask عبر `EXPO_API_HOST=0.0.0.0 python3 -m app.main` على شبكة موثوقة فقط، أو الأفضل HTTPS خلف خادم مؤمّن. لا تستخدم تشغيل development على شبكة عامة.

## بنية الـ Backend

| الخدمة | المهمة |
| --- | --- |
| Flask (`app/main.py`) | REST API والتحقق من المدخلات وإرجاع JSON |
| SQLite (`app/storage.py`) | تخزين تعديل معلومات الفعاليات إداريًا كـ `event_overrides` مع الحفاظ على IDs الأصلية |
| JSON (`backend/data/`) | مصدر الأجنحة والبوثات والبوابات والإحداثيات والفعاليات، وهو مطابق للموارد التي يقرأها Swift |
| RandomForest (`backend/models/`) | نموذج محفوظ يتوقع معامل التأخير لكل ممر اعتمادًا على **محاكاة** حركة مبنية على أوقات فعاليات وافتراضات مشاة/طاقة استيعابية |
| Swift `NavigationGraph` | المسار نفسه: Dijkstra على ممرات فعلية في بيانات الخريطة، باستخدام عوامل التباطؤ العائدة من Flask |

**لماذا SQLite؟** مناسبة لتطبيق/هاكاثون محلي وخفيف بدون خادم قواعد بيانات إضافي. إذا تعدد المستخدمون أو زادت عمليات الكتابة بالتزامن على خادم حقيقي، PostgreSQL أنسب؛ لكن الترحيل غير ضروري الآن. تظل بيانات الخرائط المرجعية في ملفات JSON لأنها ثابتة ومحزمة مع التطبيق.

### أهم الـ API

- `GET /health` فحص تشغيل الخادم.
- `GET /api/v1/dataset` حزمة البيانات الكاملة المتوافقة مع `ExpoAPI.swift`.
- `GET /api/v1/pavilions`, `/api/v1/gates`, `/api/v1/booths`, `/api/v1/events` للقوائم والفلترة.
- `GET /api/v1/events/<event_id>` تفاصيل فعالية.
- `POST /api/v1/crowd/indoor-edges` توقعات ازدحام كل ممر (الطلب الأساسي من Swift).
- `GET /api/v1/crowd/predict` مؤشر ازدحام تجريبي لمنطقة ودور ووقت.
- `GET /api/v1/crowd/model-info` معلومات مصدر النموذج والمقاييس.
- `PUT /api/v1/admin/events/<event_id>` لتعديل عنوان/وصف/تصنيف/وقت الفعالية في SQLite، محمي بمفتاح يُحدد في `EXPO_ADMIN_TOKEN` على الخادم و`X-Admin-Token` في طلبات الإدارة. لا يوضع مفتاح الإدارة في التطبيق.

### حدود البيانات والاختبارات

**هذه ليست خريطة معتمدة لإكسبو 2030 وليست قراءات زحمة حقيقية.** الأجنحة والإحداثيات والعناصر على غرار نموذج المشروع الثاني، والنموذج يتنبأ بإبطاء المشي بناءً على بيانات تدريب اصطناعية وافتراضات وفعاليات ثابتة، وليس أجهزة استشعار فعلية. الزمن والمحاكاة التفاعلية للمشي ليست GPS داخليًا حقيقيًا.

للتحقق بعد تثبيت مكتبات التطوير:

```bash
python3 -m pip install -r requirements-dev.txt
pytest -q
```

النسخة تم فحص Python فيها نحويًا، والتحقق من تحميل نموذج RandomForest وحساب توقعات نموذجية ومسارات `Swift` الأساسية نحوياً/نوعياً باستخدام compiler المتاح؛ **لم يُجرَ Xcode build على iOS Simulator** في بيئة التسليم، **ولم تُنفّذ اختبارات Flask HTTP** هنا لتعذّر تثبيت Flask دون اتصال الحزم. لذلك يلزم بناء Xcode وتشغيل Flask على الـ Mac قبل اعتبارها مُختبرة تشغيلًا بشكل كامل.

**مهم:** الواجهة والخدمات الأخرى للتطبيق الأول بقيت كما هي؛ لم نبنِ API تسجيل الحساب أو توليد الخطط أو ميزة الأصدقاء، ولم نحولها من mock إلى live. الخادم الجديد متصل بالخريطة التي تم نقلها فقط.

## تحديث تخزين المستخدمين (15 أكتوبر 2026)
أُضيفت قاعدة SQLite دائمة للحسابات والملف المهني والـCV ورحلة المستخدم والخطة وتفضيلاتها. أصبح `EXPO_API_MODE` يساوي `live` افتراضيًا في `Config/Info.plist` للمحاكي، لكن بقية وظائف الخرائط/التوصيات والأصدقاء ما زالت بالبيانات التجريبية الأصلية حفاظًا على الواجهات. **راجع `README_REAL_DATABASE_AR.md`** قبل التشغيل للاطلاع على الجداول والقيود الأمنية والميزات غير المربوطة.
