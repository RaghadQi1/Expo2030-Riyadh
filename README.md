# 2030Expo — تطبيق آيفون (SwiftUI)

واجهة أمامية كاملة لتطبيق «إكسبو الرياض 2030» مبنية من ملف فيجما `2030Expo`. التطبيق:

- مبني بـ Swift وSwiftUI.
- عربي، من اليمين إلى اليسار.
- يعمل حاليًا على **بيانات تجريبية**.
- فيه طبقة خدمات جاهزة للربط بالباك إند.

> ⚠️ **لم يُبنَ المشروع ولم يُشغَّل في Xcode بعد.** أُنشئ في بيئة Linux لا يتوفر فيها Xcode ولا SwiftUI. ما جرى فعلًا:
>
> - **فحص بنية الجمل (parse):** على كل ملفات Swift.
> - **فحص الأنواع الكامل (type-check):** على الطبقات التي لا تعتمد على SwiftUI (النماذج والبيانات التجريبية والخدمات).
>
> خطوات التحقق المطلوبة على ماك موجودة في قسم «التحقق على ماك» أدناه، وفي `HANDOFF_NOTES.md`.

---

## المتطلبات

| الأداة | الإصدار |
|---|---|
| macOS | 14.5 أو أحدث |
| Xcode | **16.0 أو أحدث** (المشروع يستخدم المجلدات المتزامنة، objectVersion 77) |
| iOS | 17.0 أو أحدث (جهاز أو محاكي) |
| Swift | 5 (وضع اللغة Swift 5 داخل Xcode 16) |
| اعتماديات خارجية | **لا يوجد.** لا Swift Package ولا CocoaPods؛ كل شيء من أطر Apple |

الخطوط المضمّنة: IBM Plex Sans Arabic وIBM Plex Sans، وكلاهما برخصة SIL Open Font License. ملفات الرخصة في `Expo2030/Resources/Fonts/`.

## فتح المشروع

### في Xcode (للبناء والتشغيل)

1. افتحي `Expo2030.xcodeproj`.
2. اختاري المخطط **Expo2030** ومحاكي آيفون (مثل iPhone 16).
3. من **Signing & Capabilities** اختاري فريقك (Team) إذا أردتِ التشغيل على جهاز حقيقي. معرّف الحزمة الحالي `com.example.expo2030` ويمكن تغييره.
4. شغّلي بـ `⌘R`.

### في Visual Studio Code (للقراءة والتعديل)

1. افتحي المجلد الجذر `Expo2030/` (الذي يحتوي `README.md`) عبر **File ← Open Folder**.
2. ثبّتي إضافة **Swift** الرسمية (swiftlang.swift-vscode) لتلوين الكود والتنقل فيه.
3. **البناء والتشغيل يحتاجان Xcode على ماك.** يمكن البناء من الطرفية:

   ```bash
   xcodebuild -project Expo2030.xcodeproj -scheme Expo2030 \
     -destination 'platform=iOS Simulator,name=iPhone 16' build
   ```

4. **اختياري:** إضافة مثل *SweetPad* تتيح البناء والتشغيل على المحاكي من داخل VS Code، ما دام Xcode مثبتًا.

## بنية المجلدات

```

├─ Expo2030.xcodeproj             ← مشروع Xcode (المجلد Expo2030/ متزامن تلقائيًا)
├─ Config/Info.plist              ← شاشة الإطلاق ولغة التطوير (أذونات الخصوصية في إعدادات البناء)
├─ API_CONTRACT.md                ← العقد المقترح مع الباك إند
├─ HANDOFF_NOTES.md               ← ملاحظات التسليم: المنجز، الناقص، الافتراضات، فروقات فيجما
└─ Expo2030/
   ├─ App/                        ← نقطة البدء، حالة التطبيق، التبويبات، زر المساعد
   ├─ DesignSystem/               ← الألوان، الخطوط، المسافات، الظلال، الأيقونات (من متغيرات فيجما)
   ├─ Components/                 ← مكونات مشتركة: أزرار، حقول، شارات ازدحام، حالات تحميل/خطأ/فراغ، QR…
   ├─ Models/                     ← نماذج البيانات (Codable) — نفس أشكال API_CONTRACT.md
   ├─ Services/
   │  ├─ Protocols/               ← عقود الخدمات (ما تعرفه الواجهات فقط)
   │  ├─ Mock/                    ← تطبيق تجريبي في الذاكرة مع تأخير ومحاكاة أخطاء
   │  ├─ Live/                    ← تطبيق حقيقي يستدعي المسارات المقترحة (APIClient)
   │  ├─ System/                  ← مراقبة الاتصال (NWPathMonitor)
   │  ├─ AppEnvironment.swift     ← اختيار الوضع mock/live + إعدادات العرض التجريبي
   │  └─ AppServices.swift        ← حاوية الخدمات (حقن التبعيات)
   ├─ MockData/                   ← البيانات التجريبية فقط (منفصلة عن الواجهات)
   ├─ Features/                   ← الشاشات حسب الأقسام
   │  ├─ Launch, Onboarding, Auth          ← 05.x، 06.x
   │  ├─ Personalization, Plan             ← 07.x، 09.x
   │  ├─ Discover                          ← 08.x
   │  ├─ Map                               ← «خريطتي» 1.x – 7.x
   │  ├─ Assistant                         ← 12.x
   │  ├─ Journey                           ← 13.x، QR 14.10 – 14.18، 17.x
   │  └─ Account                           ← 14.01 – 14.09، 16.01، الإعدادات
   └─ Resources/
      ├─ Assets.xcassets          ← الألوان، الأيقونات (SVG قالبية)، الصور، خريطتا الموقع والقاعة

```

**قاعدة التنظيم:**

- الواجهات تتعامل مع البروتوكولات في `Services/Protocols` عبر `@Environment(AppServices.self)` فقط.
- لا يوجد استدعاء شبكة أو بيانات تجريبية داخل ملفات الشاشات.

## التشغيل على البيانات التجريبية (الوضع الافتراضي)

- يعمل التطبيق في وضع `mock` تلقائيًا، ولا يتصل بأي خادم.
- تظهر شارة «نسخة تجريبية · بيانات وهمية» أسفل الشاشة دائمًا، حتى لا تُفهم العمليات التجريبية على أنها حقيقية.
- من **حسابي ← الإعدادات ← وضع العرض التجريبي** يمكن تجربة الحالات التالية:
  - زمن الاستجابة.
  - فشل الطلب التالي (حالة الخطأ).
  - محاكاة انقطاع الاتصال (17.02 / 17.04 / 17.06).
  - القوائم الفارغة.
  - رفض الصديقة لاقتراح الالتقاء (6.6).
  - تجاوز انعطاف أثناء التوجيه (2.10).
- **حساب تجريبي للدخول بالبريد:** `noura@example.com` / `Expo2030!`. يعمل داخل الوضع التجريبي فقط، وليس حسابًا حقيقيًا. يمكن أيضًا المتابعة كضيف.
- **رموز أجنحة تجريبية** لشاشة «إدخال الرمز» (14.18): `DA-09` و`AI-01` و`SP-04`.
- **مسح رمز صديقة** في المحاكي (لا كاميرا فيه): يظهر في الماسح زر «محاكاة: مسح رمز ذكرى (تجريبي)».
- **التوجيه داخل القاعة:** في الوضع التجريبي تتقدّم الخطوات كل 5 ثوانٍ، أو بالضغط على بطاقة التعليمات.

## الربط بالباك إند

1. **الاتفاق على العقد:** راجعي `API_CONTRACT.md` مع مطوّرة الباك إند، وثبّتا المسارات والحقول.
2. **مطابقة الكود:** عدّلي ما يلزم في:
   - `Expo2030/Services/Live/*.swift` (المسارات).
   - `Expo2030/Models/*.swift` (الحقول). المحوّل يستخدم `snake_case` تلقائيًا.
3. **ضبط التشغيل:** في **Product ← Scheme ← Edit Scheme ← Run ← Arguments ← Environment Variables** ضعي:

   ```
   EXPO_API_MODE = live
   API_BASE_URL  = https://api.example.com/v1/
   ```

   أو أضيفي المفتاحين إلى `Config/Info.plist` لبناءات الإصدار. إذا غاب `API_BASE_URL` يعود التطبيق إلى البيانات التجريبية تلقائيًا.

4. **قبل الإطلاق:**
   - **رموز الدخول:** خزّني رموز الدخول في Keychain بدل الذاكرة (`TokenStore` في `APIClient.swift`).
   - **الدخول الاجتماعي:** فعّلي Sign in with Apple، وأضيفي حزم Google وFacebook.
   - **الإشعارات:** سجّلي رمز APNs.
   - **الصور:** استبدلي عرض الصور المحلية بعرض روابط الصور.

   تفاصيل كل بند في `HANDOFF_NOTES.md`.

## التحقق على ماك (لم يُنفَّذ بعد)

1. افتحي المشروع في Xcode 16 وابنيه (`⌘B`). أصلحي أي أخطاء ترجمة، ولن تكون مرئية إلا هنا لأن ملفات SwiftUI لم تُترجم بعد.
2. شغّلي على iPhone 16 وiPhone SE (3rd gen) وiPhone 16 Pro Max، وتأكدي من:
   - الاتجاه من اليمين لليسار.
   - المناطق الآمنة.
   - عدم تغطية لوحة المفاتيح للحقول.
3. قارني كل قسم بلقطاته في فيجما (القائمة في `HANDOFF_NOTES.md`).
4. جرّبي الأذونات الحقيقية على جهاز:
   - الموقع (الدقيق والتقريبي).
   - الكاميرا (QR).
   - الميكروفون والتعرّف على الكلام.
   - الإشعارات.
5. شغّلي VoiceOver وأحجام الخط الكبيرة (Dynamic Type) على الشاشات الرئيسية.
