# Expo 2030 — قاعدة بيانات دائمة وربط الحسابات (تحديث 15 أكتوبر 2026)

## الهدف
الملف الأول `2030Expo-iOS(3).zip` كان يستخدم خدمات `Mock` في أغلب واجهات حسابي/رحلتي/خطتي، لذلك لم تكن بيانات المستخدم تدوم بعد إغلاق التطبيق. أضفنا في المشروع المدمج **خادم Python Flask** و**قاعدة بيانات SQLite حقيقية على القرص** مرتبطة بهوية المستخدم. **لم نبدّل تصميم الخريطة أو نماذجها**: ما زالت بياناتها ومحاكاة الازدحام ومساراتها كما هي في الدمج السابق.

**مهم:** هذه نسخة تطوير/هاكاثون وليست نظامًا مُعتمدًا للإنتاج؛ `Flask` هو خادم ويب، و`SQLite` قاعدة بيانات دائمة، وليس المقصود أن هذه بيانات زوار أو أحداث إكسبو حقيقية.

## ماذا يُحفظ الآن؟

| العنصر في التطبيق | التخزين | ملاحظات |
|---|---|---|
| إنشاء حساب بالبريد وكلمة مرور وتسجيل الدخول/الخروج | `users`, `sessions` | كلمة المرور PBKDF2-SHA256 مع salt مستقل؛ رمز الدخول عشوائي ويُخزن تجزئته فقط؛ تنتهي الجلسة بعد 14 يومًا |
| الدخول بعد إعادة فتح التطبيق | iOS Keychain + `/me` | يستعيد رمز الدخول ويتحقق منه لدى الخادم؛ إذا كان الخادم غير متاح لا نؤكد نجاح الاستعادة |
| ملف مهني: النبذة/المسمى/التعليم/الخبرات/المهارات/الروابط | `profiles` | حفظ واسترجاع بتنسيق `ProfessionalProfile` الموجود أصلًا في Swift |
| ملف CV فعلي | `cv_files` | تخزين PDF نفسه (حتى 5 MB) لا الاسم فقط، GET/POST/DELETE مقيدة بمالك الحساب |
| روابط مشاركة الملف المهني | `share_links` | رابط عشوائي، مجموعة حقول يحددها المالك، مدة صلاحية وإيقاف؛ مشاركة CV إن اختيرت تتطلب صلاحية الرابط |
| ملاحظات الرحلة | `notes` | CRUD، العنوان والإجابات والوقت وتفاصيل المرفقات |
| صور مرفقات الملاحظات | `note_attachments` | تُرفع bytes إلى قاعدة البيانات مع الطلبات ويحاول التطبيق تنزيلها إذا لم تكن موجودة محليًا |
| محفوظات الأجنحة | `saved_places` | حفظ/إزالة/استرجاع بحسب المستخدم |
| زيارات وتسجيل المسح/التأكيد | `visits` | حفظ زيارات رحلتي وتوثيق QR عند استخدام شاشة QR؛ قاعدة QR نفسها ما زالت تجريبية |
| ملخصات الرحلة المحفوظة | `summaries` | تحفظ **الناتج النهائي**؛ توليد الملخص نفسه ما زال عرضًا تجريبيًا |
| عناصر المتابعة | `follow_ups` | قاعدة بيانات وواجهات API؛ العرض الحالي لا ينشئ عناصر متابعة جديدة على الخادم تلقائيًا |
| الخطة الحالية بعد الاعتماد أو التعديل | `user_state` kind=`plan` | حساب الخطة/التعديل في Swift ما زال بالبيانات التجريبية؛ نرفع الناتج للخادم ونستعيده عند إعادة التشغيل |
| تفضيلات إنشاء الخطة | `user_state` kind=`preferences` | تُرفع عندما ينفذ المستخدم توليد خطة |
| إعدادات الحساب | `user_state` kind=`settings` | واجهات API جاهزة، لكن إعدادات النظام المعروضة في التصميم لا تُحرَّر/تُربط بهذه الجداول بعد |

**غير مفعّل بعد:** تسجيل Apple/Google/Facebook الحقيقي؛ استعادة كلمة المرور (لم تُربط بخدمة البريد بعد)؛ مزامنة عمل كاملة دون اتصال أو نقل محتويات الزائر إلى حساب جديد؛ أصدقاء حقيقيون/دعوات/مشاركة موقع/نقاط لقاء؛ حفظ صورة الملف الشخصي الفعلية (حقل `photo` مجرد مرجع)؛ محرّك توصيات حقيقي؛ الاحتفاظ بتاريخ خطط متعدد؛ جميع بيانات الخريطة الأساسية ليست بيانات واقعية. لا تدّعي الواجهة إرسال بريد إذا كانت خدمة البريد غير مهيأة.

## الملفات المضافة والمعدلة

- `backend/app/user_db.py`: تهيئة جداول SQLite، CRUD، كلمات المرور، الجلسات، فصل بيانات المستخدمين.
- `backend/app/user_api.py`: endpoints الحساب والملف المهني والـCV والملاحظات والصور والزيارات والمحـفوظات والخطط والمشاركة.
- `backend/app/main.py`: تسجيل user_api وإعداد الجداول مع Flask map API القديم؛ الحد الأعلى لطلب HTTP 6 MB.
- `Expo2030/Services/Live/PersistentServices.swift`: يوجّه ملفك، ورحلتك، والخطة الحالية إلى قاعدة البيانات عند تسجيل الدخول. الخدمات التجريبية للخريطة/الأصدقاء تبقى كما كانت.
- `Expo2030/Services/Live/APIClient.swift`: HTTP، Keychain، ورفع مرفقات PDF والصور.
- `Expo2030/Services/Live/LiveAuthService.swift`: تسجيل حساب ودخول وخروج واستعادة جلسة.
- `Expo2030/Services/Live/LiveServices.swift`: واجهات ملفك المهني ورحلتك الدائمة.
- `Expo2030/Services/AppServices.swift`: وضع هجين بدل توجيه كل الخدمة الحية إلى endpoints غير منفذة.
- `Expo2030/Features/Auth/CreateAccountView.swift`: إكمال التسجيل مباشرة في التطوير دون عرض إشعار تحقق بريد **لم يرسل فعليًا**.
- `Expo2030/Features/Account/ProfessionalProfileViews.swift`: رفع PDF فعلي، مع إبقاء التصميم.
- `Config/Info.plist`: `EXPO_API_MODE=live` و`API_BASE_URL=http://127.0.0.1:8001` للمحاكي فقط.
- `backend/tests/test_user_persistence.py`, `test_accounts_api.py`: اختبارات فصل البيانات والحفظ وواجهة HTTP.

## التشغيل على Mac + محاكي iPhone

1. فك الضغط وافتح Terminal داخل `Expo2030/backend`.
2. نفّذ:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m app.main
```

3. افحص `http://127.0.0.1:8001/health`، ثم افتح **`Expo2030.xcodeproj`** وشغّل iPhone Simulator. التطبيق يتصل بالخادم في Mac على `127.0.0.1:8001`، وينشئ قاعدة المستخدمين **`backend/instance/expo_users.sqlite3`** تلقائيًا عند أول تشغيل. قاعدة تعديلات الفعاليات منفصلة: `backend/expo.sqlite3`.
4. أنشئ حسابًا جديدًا (حروف كبيرة وصغيرة ورقم وكلمة مرور 8 أحرف على الأقل)، أدخل ملفك المهني واحفظه، ثم أغلق التطبيق تمامًا وأعد فتحه وأكّد رجوع البيانات. إذا انتهت الجلسة أدخل حسابك مرة أخرى.
5. لتشغيل اختبارات Python: `python3 -m pip install -r requirements-dev.txt` ثم `pytest -q`، أو اختبارات قاعدة البيانات فقط باستخدام stdlib: `python3 -m unittest discover -s tests -p test_user_persistence.py -v`.

**أثناء الاستخدام على iPhone حقيقي:** لا تستخدم `127.0.0.1` لأنه يشير إلى الهاتف؛ ضع عنوان IP جهاز Mac في `API_BASE_URL` وشغّل Flask على `EXPO_API_HOST=0.0.0.0` على شبكة خاصة فقط. استخدم HTTPS وخادم إنتاج عند النشر؛ إعداد HTTP المحلي غير آمن لنقل كلمات المرور عبر شبكات خارجية.

## كيف تفحص قاعدة البيانات؟

من داخل مجلد backend بعد تشغيل الخادم وتسجيل مستخدم:

```bash
sqlite3 instance/expo_users.sqlite3 '.tables'
sqlite3 instance/expo_users.sqlite3 'SELECT id,email,name,created_at FROM users;'
sqlite3 instance/expo_users.sqlite3 'SELECT user_id,updated_at FROM profiles;'
sqlite3 instance/expo_users.sqlite3 'SELECT user_id,kind,updated_at FROM user_state;'
```

يمكنك فتح ملف `.sqlite3` ببرنامج DB Browser for SQLite كذلك. **لا تشاركي ملف SQLite الذي يحتوي على الحسابات أو كلمات المرور المجزأة أو CVs أو الملاحظات**. في النسخة المسلَّمة لا توجد حسابات جاهزة ولا كلمات مرور افتراضية.

لعمل نسخة احتياطية سليمة والبرنامج يعمل:

```bash
sqlite3 instance/expo_users.sqlite3 '.backup instance/expo_users-backup.sqlite3'
```

## واجهات API المهمة

- `POST /auth/register` → إنشاء حساب وإصدار جلسة مباشرة دون تحقق بريد؛ `POST /auth/login` → جلسة للبريد وكلمة المرور الصحيحة؛ `GET /me` و`POST /auth/logout`.
- `GET/PUT /me/profile`, `POST/GET/DELETE /me/cv`.
- `GET/POST/DELETE /me/profile/share-link`, `GET /p/{slug}`, `GET /p/{slug}/cv` (فقط إذا شارك المالك حقل CV).
- `GET/PUT/DELETE /notes/{id}` (قائمة: `GET /notes`), `GET/PUT /me/note-attachments/{filename}`.
- `GET /journey/saved`, `POST /journey/saved/toggle`; `GET /journey/visits`, `POST /visits`, `PUT /journey/visits/{id}`.
- `GET/POST /journey/summaries`, `GET/PUT /journey/follow-ups/...`.
- `GET/PUT/DELETE /plans/current`, `GET/PUT /me/preferences`, `GET/PUT /me/settings`.

ما عدا رابط المشاركة العام، تتطلب هذه المسارات `Authorization: Bearer <access_token>` ويستخدم الخادم `user_id` **من الجلسة المحققة** وليس من جسم الطلب. لا تضع كلمة المرور أو access token في الداتا أو صور الاختبارات.

## تصميم التخزين والسلامة

- ملف قاعدة البيانات على القرص محليًا مع SQLite WAL وforeign keys وتقييد المفاتيح لكل مستخدم؛ لا تضيع السجلات عند خروج عملية التطبيق (لكن فقدان ملف قاعدة البيانات نفسه يفقد السجلات؛ لذلك خذي backup).
- كلمات المرور لا تخزن كنص صريح: PBKDF2-SHA256، salt مستقل، 480 ألف دورة. رموز الوصول 40 بايت عشوائي، نخزن hash الرمز في `sessions` لا الرمز نفسه، وينتهي خلال 14 يومًا.
- روابط المشاركة لا تكشف إلا الحقول المختارة؛ تنتهي ويمكن إيقافها، وتُستبدل عند إنشاء رابط جديد. مشاركة PDF تتطلب وضع حقل CV ضمن الحقول المختارة.
- لا يوجد بعد معدل حماية login من المحاولات المتكررة، ولا تحقق من ملكية البريد، ولا استضافة آمنة أو مراقبة/سجلات تشغيل أو migrations؛ هذه متطلبات قبل نشر النظام للعامة.

## فصل الجزء الحقيقي عن المحاكاة

الـ**User Database حقيقي** بمعنى تخزين دائم على القرص وREST API يعملان مع حسابات مستقلة؛ **ليس قاعدة بيانات أشخاص حقيقيين مسبقًا** ولا يعني أن خريطة إكسبو أو الازدحام مباشرة. `RandomForest` في مشروع الخريطة ما زال مدربًا على محاكاة. محرك الخطة/التوصيات/المواقع والأصدقاء يعتمد على البيانات التجريبية نفسها.

**تحديث — بدون تحقق بريد:** ينشأ الحساب في الحال مع جلسة صالحة ولا يحتاج SMTP أو OTP. الحقل `is_email_verified` يبقى `false` لأن ملكية البريد لم تتحقق. الحسابات السابقة (حتى لو كانت بانتظار رمز) يمكنها الدخول بكلمة المرور، دون فقدان الملف المهني أو بياناتها. الاستعادة عبر البريد غير مفعّلة، لذلك احفظ كلمة المرور. هذه إعدادات تطوير وليست مناسبة لإطلاق خدمة عامة بدون ضوابط أمنية إضافية.
