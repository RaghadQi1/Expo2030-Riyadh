# إعادة تخطيط الزيارة مع Gemini — Expo2030

## ما تم توصيله

- **تأخرت**: يُخصم 20 دقيقة من وقت بداية الجزء المتبقي وتُنشأ معاينة جديدة عبر Gemini، مع التحقق من أوقات الفعاليات.
- **أحتاج استراحة**: تُحجز 15 دقيقة للاستراحة ثم يعاد ترتيب باقي المحطات بطلب جديد من Gemini.
- **أضف محطة**: يُعرض للزائر بوث أو فعالية حقيقية من **البيانات التجريبية الموجودة في المشروع**، ثم يعيد Gemini اختيار الترتيب. قد تستبدل فعالية غير مثبتة لإفساح وقت لمحطة جديدة.
- **تعديل**: يفتح تخصيص الاهتمامات الحالي وإعادة توليد خطة كاملة عبر Gemini.
- **أنهي زيارتي**: يُنهي الزيارة ويمسح الخطة الحالية بعد التأكيد؛ ليس زر إعادة تخطيط.

إعادة التخطيط **تُنشئ مقترحًا فقط**؛ لا تتغير الخطة المحفوظة إلى أن تضغط «اعتماد التعديل». تخزّن الطلبات المؤقتة في جدول SQLite `plan_replan_proposals` الخاص بالمستخدم، مع تحقق من صلاحية 20 دقيقة وعدم تغيير الخطة بين العرض والاعتماد. بعد الاعتماد تُحفظ الخطة الجديدة في `user_state` مع مهلة تراجع 10 دقائق.

## تشغيل النسخة الجديدة على Mac

1. فك ضغط الملف، وافتح مجلد `Expo2030/backend` في Terminal.
2. `python3 -m venv .venv` ثم `source .venv/bin/activate` ثم `python3 -m pip install -r requirements.txt`.
3. أنشئ `.env` إن لم يوجد (`touch .env` ثم `code .env`). ضع `GEMINI_API_KEY` واسم مودل متاح **لاستخدام حسابك** في `GEMINI_MODEL`؛ لا تنسخ المفتاح إلى Xcode. لا تستخدم أسماء مودلات افتراضية دون تأكيد توفرها عبر `python3 scripts/check_gemini.py`.
4. أوقف أي Backend قديم يستخدم 8001، ثم `python3 -m app.main`.
5. افتح `Expo2030.xcodeproj`، واضبط `EXPO_API_MODE=live` في Run Scheme إن لزم، ثم `⌘R`.
6. سجل الدخول، واعتمد خطة، وجرّب «تأخرت» أو «أحتاج استراحة» أو «أضف محطة» ثم «اعتماد التعديل».

إذا كان لديك حسابات قديمة وتريد الاحتفاظ بها، **انسخ قاعدة SQLite السابقة** `backend/instance/expo_users.sqlite3` من المشروع القديم إلى `instance/` في النسخة الجديدة **بعد إيقاف السيرفر القديم**. سيُنشئ السيرفر جدول المقترحات الجديد عند بدء التشغيل من دون حذف الحسابات. احتفظ بنسخة احتياطية من SQLite قبل النقل، وأوقف أي اتصال يكتب إليها.

## الاختبار

```bash
cd backend
python3 -m unittest tests.test_gemini_planner tests.test_replanning_gemini -q
python3 -m pytest tests/test_replan_api.py -q
```

الاختبارات تعزل Gemini وتستبدل ترتيب معرّفاته بقائمة اختبارية لتجربة منطق الوقت والحفظ بلا تكلفة API. يجب تنفيذ اختبار Gemini **الحقيقي** بمفتاح المستخدم على الماك؛ فخطأ 503 بسبب ضغط خدمة Gemini قد يستمر حتى مع محاولات إعادة قصيرة. لا توجد خطة اصطناعية صامتة إذا فشل Gemini. كل الأماكن والفعاليات بيانات **محاكاة**، وأوقات المشي والحجوزات الفعلية ليست محسوبة أو مؤكدة.

## واجهات الخادم الجديدة

- `GET /plans/add-candidates` — البوثات والفعاليات الممكن زيارتها في وقت الخطة.
- `POST /plans/current/replan` — نوع التعديل encoded Swift enum، ويعيد `ReplanProposal` من Gemini.
- `POST /plans/current/replan/apply` — `{ "id": "proposal-uuid" }`، يعتمد ويكتب SQLite.
- `POST /plans/current/undo` — تراجع مقيد بمهلة 10 دقائق.

كل المسارات محمية بـBearer token، ولا تسرّب مفتاح Gemini للعميل.
